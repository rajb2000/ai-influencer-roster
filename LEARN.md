# LEARN.md — the influencer learning loop

**Project:** Log → Learn → Ledger. Every post gets logged, every week gets
mined for what worked, every dollar gets counted. This is the project's
memory — the roster's edge compounds here.

## The loop
1. **LOG** — per-persona `LOG.md`: date, post, format, hook, followers,
   engagement rate, notes. Filled after every post. Numbers only, no spin.
2. **LEARN** — this file. Sunday review extracts learnings from the week's
   logs: which hooks/formats/posting times moved followers and engagement.
   Each learning is dated, tied to the persona + post, and labeled
   VERIFIED (seen in the numbers) or HUNCH (worth testing).
3. **LEDGER** — `PROFIT_LEDGER.md`: every dollar, per persona × per stream
   (brand deals, physical, ad revenue, digital, affiliate). Actuals only.

## Rules
- Never delete a wrong call — annotate it. Strike the line, add a dated
  CORRECTION pointing at the evidence. (Raj's standing rule.)
- A learning graduates from HUNCH to VERIFIED only after it repeats.
- One bad week doesn't kill a learning; two bad weeks reopens it.
- Kill decisions come from the scoreboard (top 2 survive day 30, early kill
  <100 followers day 14) — this file explains WHY they won or lost.
